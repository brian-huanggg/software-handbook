# AI Agent 目錄

本軌道回答「怎麼讓模型自己採取行動」：從一次工具呼叫開始，到 Agent 迴圈、MCP、記憶與規劃、多 Agent 協作，最後讓 Agent 安全、可評估地在正式環境運作。
主要語言是 **Python**，專案用 `uv` 管理。範例盡量先用原生 API 從零寫出 Agent 迴圈，再介紹框架，讓讀者知道框架替你做了什麼。

**先修**：應用工程軌道 L1 與 L2（`docs/contents/ai/engineering.md`）。本軌道假設你會呼叫 LLM API、會做結構化輸出與 RAG，不再重講。

**同一個 AI 領域的其他軌道**：模型為什麼會「決定」呼叫工具，連回理論基礎軌道（`docs/contents/ai/foundations.md`）L4 的微調與對齊；Agent 的攻擊面在資安領域有更深的攻防版本。

**貫穿的例子：手冊維護 Agent**。讀者做一個幫忙維護本手冊的 Agent：

- L1：會查目錄、讀文章的工具呼叫 Agent。
- L2：能記住進度、規劃多步驟工作，例如「檢查所有文章的連結並回報壞掉的」。
- L3：由多個 Agent 分工，一個寫草稿、一個審稿、一個跑檢查。
- L4：在沙箱中執行、有權限邊界與人工核准，並有評估資料集證明它可靠。

| 層級 | 主題 | 讀完你能做到 |
| --- | --- | --- |
| L1 工具與迴圈 | 工具呼叫、Agent 迴圈、MCP | 從零寫出一個會用工具完成任務的 Agent |
| L2 記憶與規劃 | 上下文管理、記憶、規劃、長時間任務 | 讓 Agent 完成需要數十個步驟的工作 |
| L3 多 Agent 與工作流程 | 工作流程模式、多 Agent 協作、人機協作、程式碼 Agent | 為一個任務選對 Agent 架構並實作 |
| L4 正式環境的 Agent | 評估、安全、沙箱、權限、成本與治理 | 讓 Agent 在正式環境安全、可靠、可稽核地運作 |

寫目錄時沿用本檔格式：`##` 為層級、`### <節號> <名稱>` 為節、`- [ ]` 為文章。
每新增一節，同時在 `site/src/sidebar/ai.ts` 的 `agents` 軌道加上該節的標籤與目錄名稱。
