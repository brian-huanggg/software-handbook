# AI 代理人目錄

本軌道回答「怎麼讓模型自己採取行動」：從一次工具呼叫開始，到代理人迴圈、MCP、記憶與規劃、多代理人協作，最後讓代理人安全、可評估地在正式環境運作。
主要語言是 **Python**，專案用 `uv` 管理。範例盡量先用原生 API 從零寫出代理人迴圈，再介紹框架，讓讀者知道框架替你做了什麼。

**先修**：應用工程軌道 L1 與 L2（`docs/contents/ai/engineering.md`）。本軌道假設你會呼叫 LLM API、會做結構化輸出與 RAG，不再重講。

**同一個 AI 領域的其他軌道**：模型為什麼會「決定」呼叫工具，連回理論基礎軌道（`docs/contents/ai/foundations.md`）L4 的微調與對齊；代理人的攻擊面在資安領域有更深的攻防版本。

**貫穿的例子：手冊維護代理人**。讀者做一個幫忙維護本手冊的代理人：

- L1：會查目錄、讀文章的工具呼叫代理人。
- L2：能記住進度、規劃多步驟工作，例如「檢查所有文章的連結並回報壞掉的」。
- L3：由多個代理人分工，一個寫草稿、一個審稿、一個跑檢查。
- L4：在沙箱中執行、有權限邊界與人工核准，並有評估資料集證明它可靠。

| 層級 | 主題 | 讀完你能做到 |
| --- | --- | --- |
| L1 工具與迴圈 | 工具呼叫、代理人迴圈、MCP | 從零寫出一個會用工具完成任務的代理人 |
| L2 記憶與規劃 | 上下文管理、記憶、規劃、長時間任務 | 讓代理人完成需要數十個步驟的工作 |
| L3 多代理人與工作流程 | 工作流程模式、多代理人協作、人機協作、程式碼代理人 | 為一個任務選對代理人架構並實作 |
| L4 正式環境的代理人 | 評估、安全、沙箱、權限、成本與治理 | 讓代理人在正式環境安全、可靠、可稽核地運作 |

寫目錄時沿用本檔格式：`##` 為層級、`### <節號> <名稱>` 為節、`- [ ]` 為文章。
每新增一節，同時在 `site/src/sidebar/ai.ts` 的 `agents` 軌道加上該節的標籤與目錄名稱。

## L1 工具與迴圈：讓模型採取行動

L1 的目標是不用任何框架，從零寫出一個會查資料、會用工具完成任務的代理人。

### 1.1 什麼是代理人

- [ ] 從聊天機器人到代理人：誰決定下一步
- [ ] 工作流程 vs 代理人：固定流程與自主決策
- [ ] 代理人的組成：模型、工具、迴圈、記憶
- [ ] 什麼時候不該用代理人

### 1.2 工具呼叫

- [ ] 工具呼叫的原理：模型只產生「想呼叫什麼」
- [ ] 定義工具：名稱、描述與參數 schema
- [ ] 執行工具並把結果回傳給模型
- [ ] 平行工具呼叫
- [ ] 工具錯誤的處理與回報

### 1.3 代理人迴圈

- [ ] ReAct：思考、行動、觀察
- [ ] 從零實作代理人迴圈
- [ ] 停止條件：完成、步數上限、預算上限
- [ ] 追蹤每一步：讓代理人的行為看得見
- [ ] 手冊維護代理人 v1

### 1.4 工具設計

- [ ] 好工具的條件：單一職責、清楚的描述
- [ ] 工具的輸出格式：給模型看的，不是給人看的
- [ ] 工具的粒度：少而強 vs 多而細
- [ ] 唯讀工具與有副作用的工具

### 1.5 Model Context Protocol（MCP）

- [ ] MCP 解決什麼問題
- [ ] 架構：host、client、server
- [ ] tools、resources、prompts
- [ ] 用 Python 寫一個 MCP server
- [ ] 把 MCP server 接進現有的 AI 工具
- [ ] 傳輸方式與認證

## L2 記憶與規劃：完成長時間的任務

L2 的目標是讓代理人完成需要數十個步驟、超出單一上下文視窗的工作。

### 2.1 上下文管理

- [ ] 上下文視窗是代理人最稀缺的資源
- [ ] 上下文工程：放什麼、不放什麼
- [ ] 截斷、摘要與壓縮
- [ ] 把大型工具輸出移出上下文

### 2.2 記憶

- [ ] 短期記憶與長期記憶
- [ ] 以檔案為記憶：筆記、待辦清單、進度檔
- [ ] 以向量檢索為記憶
- [ ] 記憶的寫入、更新與遺忘
- [ ] 跨工作階段的延續

### 2.3 規劃與推理

- [ ] 先規劃再執行
- [ ] 任務分解與待辦清單
- [ ] 反思與自我修正
- [ ] 推理模型在代理人中的角色
- [ ] 手冊維護代理人 v2：多步驟的連結檢查

### 2.4 長時間任務

- [ ] 檢查點與恢復
- [ ] 背景執行與非同步通知
- [ ] 處理中途失敗
- [ ] 進度回報與中斷

## L3 多代理人與工作流程：選對架構

L3 的目標是為一個任務判斷該用固定工作流程、單一代理人，還是多個代理人，並說清楚取捨。

### 3.1 工作流程模式

- [ ] 提示串接（prompt chaining）
- [ ] 路由
- [ ] 平行化：分段與投票
- [ ] 協調者與執行者（orchestrator–workers）
- [ ] 評估者與最佳化者（evaluator–optimizer）

### 3.2 多代理人系統

- [ ] 為什麼要多個代理人：專業分工與上下文隔離
- [ ] 子代理人與任務委派
- [ ] 代理人之間的溝通與共享狀態
- [ ] 多代理人的失敗模式
- [ ] 手冊維護代理人 v3：寫稿、審稿、檢查分工

### 3.3 人機協作

- [ ] 人工核准點：哪些動作需要人確認
- [ ] 讓人能中途介入與修正
- [ ] 回報與交接：讓人看懂代理人做了什麼

### 3.4 程式碼代理人

- [ ] 程式碼代理人怎麼運作：讀、改、執行、驗證
- [ ] 用測試與型別檢查當作回饋
- [ ] 專案指示檔與技能：教代理人你的慣例
- [ ] 與程式碼代理人協作的工作方式

### 3.5 框架與 SDK

- [ ] 框架替你做了什麼：從自己的迴圈到框架
- [ ] 代理人 SDK 與框架的比較與取捨
- [ ] 什麼時候不要用框架

## L4 正式環境的代理人：安全、可靠、可稽核

L4 的目標是讓代理人在正式環境運作時，你能證明它可靠、限制它的破壞範圍，並為它的成本與行為負責。語氣是同儕討論取捨。

### 4.1 代理人評估

- [ ] 為什麼評估代理人比評估單次回答難
- [ ] 任務成功率與軌跡評估
- [ ] 建立代理人的評估環境與資料集
- [ ] 多次執行的穩定性：pass@k 與 pass^k
- [ ] 回歸測試與基準

### 4.2 代理人安全

- [ ] 代理人的攻擊面：工具、資料、權限
- [ ] 間接提示注入：從網頁、文件、工具輸出進來的指令
- [ ] 資料外洩與危險的工具組合
- [ ] 最小權限：只給代理人需要的工具與憑證
- [ ] 秘密管理：不讓代理人看到或洩漏憑證

### 4.3 沙箱與權限

- [ ] 在容器與虛擬機裡執行代理人
- [ ] 檔案系統與網路隔離
- [ ] 權限模式與核准政策
- [ ] 不可逆動作的防護
- [ ] 手冊維護代理人 v4：在沙箱中安全執行

### 4.4 營運與治理

- [ ] 代理人的可觀測性：追蹤、稽核紀錄
- [ ] 成本控制：步數、token 與預算上限
- [ ] 可靠性：重試、冪等與部分失敗
- [ ] 組織的代理人使用政策與責任歸屬
- [ ] 代理人的未來：能力、限制與該保持懷疑的地方
