# 工具與效率目錄

本領域寫給已經會寫程式、想把日常開發工具用得更熟的人：編輯器與 IDE、終端機、Git 介面、資料庫用戶端、API 工具、除錯與效能分析工具。
目標不是背功能清單，而是理解每一類工具**解決什麼問題、核心概念是什麼**，換一個產品也能很快上手。

本領域**依工具類別分組**，不分 L0–L4；每一組都獨立，可以按需要挑著讀。沒有貫穿專案。

**先修**：計算機科學領域的「命令列與開發工具」（`docs/contents/cs.md` 的 T 組）。那裡講指令與概念的最小集合，這裡講各類工具的完整用法與工作流。

| 類別 | 讀完你能做到 |
| --- | --- |
| 編輯器與 IDE | 用導覽、重構、除錯與外掛把一個專案讀懂、改穩 |
| 終端機與 Shell 環境 | 配置順手的終端機，用多工、別名與歷史搜尋加速日常操作 |
| Git 工具 | 用圖形介面與進階指令閱讀歷史、整理 commit、處理衝突 |
| 資料庫用戶端 | 連線、查詢、看執行計畫、匯出匯入並安全地操作資料 |
| API 與網路工具 | 發請求、看回應、重現並除錯一個 HTTP 問題 |
| 除錯與效能分析 | 用除錯器與 profiler 定位錯誤與瓶頸 |

## 寫作與維護規則（工具會更新，內容會過期）

工具改版很快，本領域用下列規則把過期的影響降到最低：

1. **教能力，不教產品**：標題寫「在 IDE 裡除錯」，不寫「某某 IDE 2026 指南」。每篇以一到兩個代表工具示範，並簡短提及替代品。
2. **講穩定的部分**：概念、工作流、快捷鍵邏輯與命令列為主；不寫選單點擊路徑。
3. **每篇標示驗證版本**：frontmatter 的 `verified` 欄位記錄工具名稱、版本與驗證日期（格式見下）。
4. **少用截圖**：截圖最先過期、重做成本最高；能用文字或指令表達就不放圖。
5. **連到官方文件**：精確的操作步驟交給官方文件，本書只講「為什麼」與「什麼時候用」。
6. **定期複查**：每 6 到 12 個月，依 `verified.date` 排序重新檢查最舊的文章。

```yaml
verified:
  tool: DBeaver
  version: "25.2"
  date: 2026-11-13
```

與其他領域的分界：Git 的指令概念、Docker 與 Kubernetes 等基礎設施工具屬於 CS 與 DevOps 領域；本領域只寫「開發者每天互動的工具」。

寫目錄時沿用本檔格式：`##` 為類別、`### <節號> <名稱>` 為節、`- [ ]` 為文章。
每新增一節，同時在 `site/src/sidebar/tools.ts` 加上該節的標籤與目錄名稱。
