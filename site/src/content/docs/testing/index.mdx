---

本領域寫給想成為資深 QA 專家的工程師：不只會寫自動化測試，還能判斷該測什麼、測到什麼程度、怎麼讓整個團隊對品質負責。主要語言是 Go，測試工具盡量選 Go 生態系；少數非 Go 工具（如 k6、axe-core）會說明為什麼選它。

**先修**：[後端](/backend/) L1。你需要會寫 Go，並會用 `testing` 套件寫基本的單元測試；語法層面的東西不再重講。

| 層級 | 主題 | 讀完你能做到 |
| --- | --- | --- |
| L0 品質思維 | 測試的目的、缺陷成本、QA 的角色、測試原則 | 說清楚一個測試在保護什麼 |
| L1 測試設計 | 黑箱與白箱技術、探索式測試、缺陷報告 | 有系統地設計測試案例，寫出讓人修得動的缺陷報告 |
| L2 自動化分層 | 單元、整合、契約、API、UI 與 E2E | 為每一種風險選對測試層級並實作 |
| L3 測試套件工程 | 測試資料與環境、不穩定測試、覆蓋率與變異測試、CI 品質閘門 | 讓一套持續長大的測試保持可信又快速 |
| L4 非功能與品質策略 | 效能、韌性、安全、無障礙、正式環境測試、帶領品質工作 | 為一個產品擬定並推動品質策略 |

## 兩個受測系統

- **短網址服務**：後端領域自己寫的 API，用來練單元、整合、契約、API 與效能測試。你看得到也改得動它的每一行程式碼。
- **Gitea**：熱門的開源 Git 服務，Go 後端加 Web 前端，用來練 UI、E2E、探索式與無障礙測試。它能用單一執行檔加 SQLite 在本機跑起來，repo 裡也有真實的 Playwright E2E 測試可以讀。這是「測一個不是你寫的系統」的練習。

## 與其他領域的分工

安全測試在這裡只講到「QA 在流程裡要涵蓋什麼」；攻擊手法與滲透測試在[資安](/cyber/)。CI 流水線怎麼建、部署策略怎麼運作，在 [DevOps](/devops/)；本領域只講測試怎麼接進去、品質閘門怎麼設。
